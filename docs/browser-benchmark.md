# 浏览器方案对比

2026-10-22 在 Windows 本机使用 Playwright 1.64.1 实测。每种方案运行 6 轮，每轮全新进程，获取广东珠江、云南都市的前一天、当天、后一天节目单，共 36 个频道日期检查。数据经生产适配器解析、规范化和去重后计算 SHA-256；所有成功方案跨轮次、跨浏览器的数据哈希一致。

| 方案 | 成功检查 | 耗时中位数 | 最慢一轮 | 浏览器内存采样最大值 |
| --- | --- | --- | --- | --- |
| 纯 HTTP | 18/36 | 0.85 秒 | 1.27 秒 | 0 MiB |
| 两站均用 Headless Shell | 36/36 | 3.63 秒 | 3.85 秒 | 725 MiB |
| 两站均用完整 Chromium | 36/36 | 5.30 秒 | 11.28 秒 | 1062 MiB |
| 云南 HTTP + 广东精简 Shell | 36/36 | 2.55 秒 | 2.86 秒 | 289 MiB |

纯 HTTP 无法获得广东需要网页签名的接口数据，不能替代全部浏览器请求。生产采用混合方案：云南 HTTP 首次请求最多 8 秒，失败后回退浏览器；广东保留官方网页签名，阻止图片、字体、媒体、样式及站外资源。网页已加载但签名模块初始化失败时，恢复原资源策略重试一次；连接失败不重复导航。CI 只安装 Headless Shell。

内存是请求完成后的浏览器进程工作集采样，非峰值；耗时包含网络，结果不代表 GitHub Linux runner 的速度或源站可用性保证。本站接口的 403、源站超时仍按独立源异常记录，不影响已有合格 EPG 发布。

复测需同时安装两种 Chromium：

```sh
npm ci
npx playwright install --with-deps chromium
npm run benchmark:browsers -- --rounds 6 --output output/browser-benchmark
```

输出 `results.json`（逐轮、逐站、逐日期结果与哈希）和 `summary.txt`。不要将基准测试安装命令替代生产的 `--only-shell` 安装命令。基准测试捕获访问失败用于比较；查看成功检查数判断可用性。
